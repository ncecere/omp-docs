<Callout type="warn" title="Retired in v0.4.0">
Open MCP Portal no longer trusts external agent platforms. This page remains so old links keep working. See the [v0.4.0 release notes](/docs/releases/v0-4-0).
</Callout>

Open MCP Portal v0.3.0 added a way for an external agent platform to say which person an agent was acting for. v0.4.0 removed it completely.

## What was removed

- **Admin › Trusted agent platforms** and its API operations under `/v1/admin/agent-platforms`.
- **Relay service accounts.** Migration `00034` switched off every service account that was marked as a relay and revoked its keys. Those accounts now show as **Retired** and are read-only. You can still view and revoke their old keys, but creating a key, enabling, updating or deleting the account is refused with `service_account_retired`.
- The per-capability **Present person** setting, **Require a present person** on servers, **Let my agents use this key** on people's own keys, and the `act` claim in the identity token.
- The `omp_agent_token_total` metric.

An inbound `MCP-Gateway-Identity` header on `/mcp/{slug}` is now refused with HTTP `403`, before authentication: "Inbound external identity is retired. Remove the identity header and use an ordinary MCP credential." The identity token that the portal sends **to** MCP servers is unchanged.

The migration is forward-only: rolling it back restores neither trust nor credentials. Old call records keep their agent attribution, read-only, and the audit log keeps its history. The migration also writes one system audit entry (`agent_platform.retire`) with the counts and IDs it affected.

## What to use instead

| You used it for | Use now |
|---|---|
| An agent calling tools as a person | The person's own MCP credential: OAuth sign-in from their MCP client, or their own [API key](/docs/use/api-keys) |
| An agent or job calling tools for a team | A new ordinary [service account](/docs/teams/service-accounts) and key, with reviewed gateway grants and tool scopes. Don't try to reuse a retired relay account |
| A team's job that needs an account on another service (GitHub, Google) | A [team service connection](/docs/teams/service-connections), assigned to that service account |
| One portal in front of another | On the upstream portal's registration of the downstream portal, switch **Send identity token** off, and give it an ordinary MCP credential for the downstream portal |

The pi coding client is unaffected: it is an ordinary MCP client.
