---
title: Troubleshooting
description: What 401, 403, 404, 429, missing tools, consent and approval links, unexpected sign-outs and repeated consent prompts mean when you use Open MCP Portal's gateways.
---

| Symptom | Likely cause | What to do |
|---|---|---|
| `401` with `error="invalid_token"` | The key or token was revoked or expired, you're suspended, the service account is turned off or its team archived, an OAuth token was used on another gateway than the one it was issued for, or an OAuth app's sign-in ran out (it lasts about 180 days from the last time you signed it in, unless your administrator changed `OAUTH_REFRESH_ABSOLUTE_TTL`; [Connected apps](/docs/use/connected-apps#how-long-a-connection-lasts) shows **Sign-in expires**) | Sign in again, or use a valid key. A script or agent that runs without a person should use a key or a service account |
| `403` "Inbound external identity is retired" | The request carries an `MCP-Gateway-Identity` header. The portal no longer accepts a caller's identity in that header | Remove the header and use an ordinary key or OAuth sign-in |
| `404 Gateway not found` | The gateway doesn't exist or is turned off, you (or the service account) can't use it, its team is archived, your grant expired, or the key is limited to other gateways | Check the URL under My gateways, and the key's gateways under API keys. For a platform gateway, you may be able to [request access](/docs/use/access-requests) |
| `429` and JSON-RPC `-32029` "Rate limit exceeded" | You, your key or app, your service account, or the gateway as a whole went over its requests per minute. `Retry-After` says when to retry | Wait and retry; ask a platform admin if the limit is too low for your use |
| `429` with `data.limit` `server_per_minute` or `server_busy` | The server's own quota of forwarded calls per minute, or its cap on concurrent calls, was reached. Nothing was sent to it | Wait and retry; if it keeps happening, ask the server's team, who set these limits |
| A tool you expect is missing | It isn't selected in this gateway, its server is turned off, unpublished, retired (sunset) or its change isn't approved yet, your team role is below the tool's minimum, it's outside your key's or app's [tool scope](/docs/use/tool-scopes), its server is labelled above the gateway's sensitivity ceiling, the gateway's tool policy for it needs review after the tool changed, or the gateway renamed it | Check the gateway's page under My gateways (it shows your own access, without a key's scope); ask the gateway's team |
| `Unknown tool` (`-32602`) on a call that worked before | The same reasons, changed since your client listed the tools: every call is checked again | Ask your client to list tools again |
| `-32042` with a link (or, from a 2026-07-28 client, a tool error or `input_required` result carrying a link) | The tool needs your account on another service, needs you to sign in to its MCP server, needs your permission for this server to use your account, or needs **your own key for the server** (the link opens a page that names the server and the address the key goes to) | Open the link in your browser, connect, allow or paste your key, then run the tool again. See [Connecting accounts](/docs/use/connecting-accounts) and [Keys for servers](/docs/use/keys-for-servers) |
| `-32042` (or a tool error or `input_required` result) saying "… needs human approval" with a link to `/approvals/…` | A rule requires a person's approval for this exact call | Open the link, or ask a reviewer to; once it's approved, send the identical call again within its validity. See [Approving sensitive tool calls](/docs/use/approvals) |
| A tool error "Approval was denied" | A reviewer denied this exact call. Retrying doesn't ask again | Open the link and choose **Request new attempt** if the call is still needed |
| A tool error "Approval was spent, but the upstream result is not confirmed", or **Authorization spent — execution is not confirmed** on the request's page | The approved attempt was used, but the portal can't tell whether the server acted | Check the destination before requesting another attempt; repeating the call may do it twice |
| `-32010` with `approval_unavailable` | The approval check couldn't run, or you already have 20 approval requests pending | Retry later, or let some requests finish |
| `-32010` with `authority_changed` | Your access or the policy changed while the call was being checked | Retry the original request |
| Asked to allow a server you already used | The server moved to another host, or now needs another service, which ends the permission | Check the server and team named on the page, then allow it. See [Allowing a server](/docs/use/connecting-accounts#allowing-a-server) |
| You were signed out of the portal unexpectedly | Your session was signed out, by you from another browser or by a platform admin; it was idle longer than your installation allows (`SESSION_IDLE_TIMEOUT`); it reached its absolute limit; or you were suspended, which ends every session for good | Sign in again. See [Browser sessions](/docs/use/sessions) |
| Signing in is refused for a new person, as if suspended | Your company's directory must provision everyone before their first sign-in (SCIM enrollment is required), and it hasn't provisioned you, more than one directory account matches you, or yours is inactive | Ask your directory or platform admin to provision you |
| No email notifications | Email isn't set up, you haven't signed in since the upgrade (your address counts as verified only after a sign-in), or your switch is off | See [Notification preferences](/docs/use/notification-preferences) |
| You are asked for your key again, for a server you entered it for | The server answered a call with `401` or `403`, so the key is marked rejected and isn't sent again; or the team moved the server to another origin or changed where the key goes, which deletes everyone's keys | Paste the key again under Account › My connections › Keys for servers. If the `403` was a permission problem on one tool, fix that first. See [Keys for servers](/docs/use/keys-for-servers#keys-for-servers-on-my-connections) |
| `-32010` with `service_account` | The server wants each person's own key, which a service account never has | Use those tools as yourself |
| `-32010` with `service_connection_missing`, `service_connection_not_allowed`, `service_connection_needs_reconsent` or `service_connection_lapsed` | A service account called a tool that needs a shared team connection, and none is assigned to it and allowed for this server, or the connection needs reconnecting, or the person who connected it is no longer an owner or admin of the team | Ask the team's owners or admins to review **Service accounts** › **Connections** ([Service connections](/docs/teams/service-connections)) |
| `-32010` with `circuit_open` | The server failed five times in a row, so the portal stops sending it calls for 30 seconds and then tries one. Nothing was sent | Wait (`data.retryAfterSeconds`) and retry; tell the server's team if it persists |
| `-32602` "argument X is fixed by this gateway" or "argument X is not allowed by this gateway" | The gateway fixes that argument or allows only some values | Use the values in the tool's listed schema |
| `-32602` "Task not found", `-32021`, or `-32010` with `task_capacity` or `task_busy` | A task handle is unknown, expired or belongs to another credential; the request didn't declare the Tasks extension; you have too many unfinished tasks; or the task is busy | See [Long-running tools](/docs/get-started/use-from-your-agents#long-running-tools-tasks) |
| `-32010` with `machine_auth_unavailable` | The server uses **the portal's own OAuth client** and the portal couldn't get a token from the server's authorization server (unreachable, an error answer, or an address that is no longer allowed). The server wasn't contacted | Try again later, or tell the server's team: they check the token endpoint and the client ([Register a server](/docs/teams/register-a-server#the-portals-own-oauth-client)) |
| A server's Health, **Test connection** or a call record shows the error class `tls` | The portal couldn't complete a TLS handshake with the server: its certificate isn't trusted (the team may need to add its private CA), isn't valid for the host name, or has expired; the server refused the portal's client certificate, or wants one; or it doesn't speak TLS 1.2 or newer. The message says which | Tell the server's team, who change its [TLS settings](/docs/teams/register-a-server#tls-to-the-server) |
| `-32010` with `provider_disabled` or `provider_unavailable` | The service's auth provider is turned off, or the service didn't answer when the portal refreshed your token | Try again later, or ask a platform admin |
| `-32010` with `provider_not_allowed` | The tool's service has an access list that doesn't include the server's team or the server, so your account isn't sent to it. You get no link to open | Ask a platform admin to add the team or server to the provider's access list ([Auth providers](/docs/administer/auth-providers#who-may-use-a-provider)) |
| The connect link says "This link was made for someone else" | You're signed in to the portal as another person, or someone else's tool produced the link | Sign in as yourself, then run the tool again for a new link |
| The connect link says "This link expired" | Links last 10 minutes and work once | Run the tool again |
| The browser keeps asking for consent | The app isn't trusted and you disconnected it, or it connects to a different gateway (one consent per gateway) | Allow it once per gateway |
| A trusted client such as Claude Code shows a notice with **Continue** and **Cancel** instead of connecting | It is the first time you sign that client in to this gateway from this computer (a redirect to `localhost`); it is asked once per person, client and gateway, and again after you disconnect the app. See [Trusted clients](/docs/administer/trusted-clients#the-first-sign-in-from-this-computer) | Choose **Continue** if you started the sign-in, **Cancel** if you did not |
| The browser shows "Can't connect this app" | The app's request was refused before anything was shared: an unknown app, a redirect address it never registered, or a metadata document the portal can't fetch. Since v0.2.2 the portal looks at the app only after you sign in, so you may see this page after signing in | Try connecting again from the app; if it persists, tell the app's maker or a platform admin |
| A tool of a public server fails with a message such as "Authentication is not allowed", or with `401` or `403`, although adding the server and reading its tools worked | The server refuses the portal's identity token, which is sent as `Authorization: Bearer …` on every real call and on a manual **Test connection** (not on discovery, refresh or scheduled checks). Test catches a server that answers `401` or `403` to it; a server that refuses only when a tool runs, like DeepWiki's public endpoint, passes Test. A server registered since v0.2.2 with no authentication on a public host starts with the switch off, so this mostly affects servers registered earlier, or ones where the switch was turned on | Ask the server's team to turn off **Send identity token** in the server's settings. A team member can check the failing call's **Identity token** detail to see whether the token was sent. See [Send identity token](/docs/teams/register-a-server#send-identity-token) |
| **Test connection** fails with "The server accepts the portal's requests without its identity token but refused them with it" | The server answered `401` or `403` to the identity token a manual Test sends, and accepted the same request without it | Turn off **Send identity token** in the server's settings, or have the server accept the token. See [Send identity token](/docs/teams/register-a-server#send-identity-token) |
| A tool result is an error with `isError: true` | The MCP server ran the tool and reported a failure | Read the message; it comes from the server, not the portal |

Requests and responses are limited to 1 MiB, and a call waits at most the server's timeout (at most 120 seconds), including any automatic retries. A larger answer fails as too large.

The team that owns a gateway can look up a call in its call records (owners and admins) if you tell them roughly when you made it and through which gateway.
