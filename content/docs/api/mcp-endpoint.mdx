Every gateway is served at `<APP_URL>/mcp/{slug}`, for example `https://mcp.example.com/mcp/support`.

## Transport

- **Streamable HTTP, stateless.** Only `POST`; `GET` and `DELETE` are `405`. No MCP session is kept between requests and no session ID is issued; any replica can answer.
- **Responses are JSON.** Notifications get `202`. The one exception is a `tools/call` that carries `_meta.progressToken` from a client that accepts `text/event-stream`: it is answered as a server-sent event stream of progress events and then the result (see [MCP protocol support](/docs/server-authors/mcp-protocol#streaming-progress)).
- **JSON-RPC batches** are `400`.
- **Protocol versions** `2026-07-28`, `2025-11-25`, `2025-06-18`, `2025-03-26` and `2024-11-05`, chosen **per request**. An older client negotiates on `initialize` as before. A 2026-07-28 request carries `_meta` with its protocol version and capabilities and the `MCP-Protocol-Version`, `Mcp-Method` and `Mcp-Name` headers, which the portal checks against the body. A request that is neither valid legacy nor valid modern is `400`. See [MCP protocol support](/docs/server-authors/mcp-protocol).
- **Origin.** A browser request with a foreign `Origin` is `403`.
- **No inbound identity.** A request that carries an `MCP-Gateway-Identity` header, whatever its value and method, is refused with `403` before authentication: "Inbound external identity is retired. Remove the identity header and use an ordinary MCP credential." (since v0.4.0). A portal that registers another portal as a server must switch **Send identity token** off for it.
- **Size.** Requests and responses are at most 1 MiB.

## Authentication

`Authorization: Bearer <credential>`, one of:

- an OAuth access token (`ompat_…`) issued by the portal for **this** gateway (see [OAuth endpoints](/docs/api/oauth-endpoints));
- a personal API key (`omp_…`);
- a service account key (`omp_sa_…`).

Without a valid credential, the answer is `401` with a challenge pointing at the gateway's protected-resource metadata, which is how MCP clients discover OAuth sign-in:

```http
HTTP/1.1 401 Unauthorized
WWW-Authenticate: Bearer resource_metadata="https://mcp.example.com/.well-known/oauth-protected-resource/mcp/support"
```

An OAuth token for another gateway gets `401` with `error="invalid_token"` and that gateway's challenge.

## Methods

| Method | Served from |
|---|---|
| `initialize`, `ping` (legacy requests) | The portal. `initialize` advertises `tools` and `prompts`, and `resources` (`subscribe: false`, `listChanged: false`) only when the gateway selects a resource or template |
| `server/discover` (2026-07-28 requests) | The portal: the supported versions, the same capabilities, and its identity. It also advertises the MCP Tasks extension, `io.modelcontextprotocol/tasks`. Results are cacheable only privately |
| `tools/list`, `prompts/list`, `resources/list`, `resources/templates/list` | The portal's stored, approved definitions, filtered for the caller, paged (512 KiB per page) with an opaque cursor. Servers aren't contacted. Tools carry the gateway's [curation](#names) and `readOnlyHint` and `destructiveHint` set from the owner's class. Tools outside the credential's [tool scope](/docs/use/tool-scopes), and servers above the gateway's sensitivity ceiling or past their sunset, aren't listed |
| `tools/call`, `prompts/get`, `resources/read` | Checked (access, scope, curation constraints, [approval rules](#calls-that-need-approval)), then forwarded to the server with the [identity token](/docs/server-authors/identity-token) |
| `tasks/get`, `tasks/update`, `tasks/cancel` (2026-07-28 requests) | Checked again, then sent once to the server that holds the task. See [Tasks](#tasks) |

`resources/subscribe` and `resources/unsubscribe` are "method not found", and so are `ping` and `logging/setLevel` for 2026-07-28 requests. Sampling and roots aren't supported. The portal asks the client a question (a URL elicitation, to connect an account) only as the consent answers described below, and relays a server's own elicitation to a client that can answer it. A client's cancellation isn't recorded as an error.

## Names

- Tools and prompts: `{server-slug}__{name}` by default, for example `status__check_outage`. A gateway's owners can [curate](/docs/teams/curating-gateway-tools) a selected tool: give it another exposed name (such as `check_outage`), rewrite its description, and fix or narrow its arguments, which the listed input schema then reflects. The curated name is the only name the gateway answers to, and an exact name in a [tool scope](/docs/use/tool-scopes) means that exposed name. A fixed argument the client sends with another value, or a value outside an allowed list, is refused with `-32602` before anything is forwarded. Prompts and resources can't be curated.
- Resources: `omp://{server-slug}/{uri}`, for example `omp://status/status://services`. Templates get the same prefix, so their variables are unchanged: `omp://status/status://services/{service}`.

A `resources/read` must name a selected resource's URI exactly, or match a selected template (simple `{var}` and reserved `{+var}` expressions; no empty values, and no `.` or `..` path segments, also when percent-encoded). The `contents[].uri` of a result are rewritten to the exposed form.

## HTTP statuses

| Status | When |
|---|---|
| `200` | A JSON-RPC answer (results and JSON-RPC errors alike) |
| `202` | A notification |
| `400` | A malformed request, a batch, an unsupported `MCP-Protocol-Version`, a 2026-07-28 request whose `_meta` or headers are missing or don't match the body (`-32602`, `-32020`, `-32022`), or a task method from a request that didn't declare the Tasks extension (`-32021`) |
| `401` | No valid credential: missing, wrong, revoked or expired; a suspended person; a service account that's turned off, deleted or whose team is archived; an OAuth token for another gateway |
| `403` | A foreign `Origin`, or any `MCP-Gateway-Identity` header in the request |
| `404` | The gateway doesn't exist, is turned off, or its team is archived; or the caller can't use it, including a key limited to other gateways. All look the same. (A 2026-07-28 request for a method the portal doesn't implement is also `404`, with `-32601`) |
| `405` | `GET` or `DELETE` |
| `429` | A rate limit, with `Retry-After`: the caller's limits, or the upstream server's own quota (`server_per_minute`) or concurrency cap (`server_busy`). Refused before any approval is spent. The JSON-RPC code is `-32029` for older clients and `429` for 2026-07-28 requests |

Counted responses carry `RateLimit-Limit`, `RateLimit-Remaining` and `RateLimit-Reset` for the caller's own tightest limit.

## JSON-RPC errors

| Code | Meaning | `data` |
|---|---|---|
| `-32602` | `Unknown tool` / `Unknown prompt`: not on this gateway for this caller now (not selected, unavailable, a role too low, outside the credential's tool scope). Also invalid params (including a curated argument constraint), an invalid `requestState`, `Task not found`, and, for 2026-07-28 requests, a resource that isn't found | |
| `-32002` | `Resource not found` for older clients: a read the caller may not make, or the server's own "not found" | |
| `-32020` | HeaderMismatch (2026-07-28): a required header is missing, differs from the body, or can't be carried | |
| `-32021` | A task method from a request that didn't declare the Tasks extension (2026-07-28) | `requiredCapabilities` |
| `-32022` | UnsupportedProtocolVersion (2026-07-28) | `supported`, `requested` |
| `-32603` | The MCP server's answer was invalid (for example a malformed elicitation request) | |
| `-32042` | `URLElicitationRequiredError`: the person must connect an account, allow a server to use it, sign in to an OAuth-protected server, enter their own key for a server, or have this exact call approved. The message also contains the link. Sent to older clients only; a 2026-07-28 client gets an `input_required` result or a tool error instead | `elicitations[0]`: `mode: "url"`, `elicitationId`, `url`, `message` |
| `-32010` | Refused with a reason the caller may know. A prompt or resource read from a 2026-07-28 client that can't take URL elicitation gets this for "connect your account", with the link in the message | `reason`: `service_account`, `provider_disabled`, `provider_unavailable`, `provider_not_allowed`, `insufficient_scope`, `not_connected`, `missing_scopes`, `needs_reconsent`, `server_not_allowed`, `authorization_declined`, `machine_auth_unavailable` or `input_required`; for a service account's shared connection `service_connection_missing`, `service_connection_not_allowed`, `service_connection_needs_reconsent` or `service_connection_lapsed`; `approval_unavailable`, `authority_changed`; `circuit_open` (with `retryAfterSeconds`); `task_capacity`, `task_busy`, `task_input_unsupported`. `provider` where one applies |
| `-32029` | Rate limit exceeded | `reason: "rate_limited"`, `limit` (including `server_per_minute` and `server_busy`), `limitPerMinute`, `retryAfterSeconds` |
| `-32001` | An HTTP-level refusal (with `401`, `403` or `404`), such as "Gateway not found" or the refused `MCP-Gateway-Identity` header | |
| `-32601` | Method not found | |

A `-32042` answer, for example:

```json
{"jsonrpc": "2.0", "id": 7, "error": {"code": -32042,
 "message": "github-tools__create_issue needs your GitHub account (repo). Open https://mcp.example.com/connect/github?request=Zk3… to connect it, then try again.",
 "data": {"elicitations": [{"mode": "url", "elicitationId": "Zk3…",
   "url": "https://mcp.example.com/connect/github?request=Zk3…",
   "message": "Connect your GitHub account (repo) to use github-tools__create_issue in the support gateway."}]}}}
```

The portal is stateless, so it never sends `notifications/elicitation/complete`: the person runs the tool again after connecting, or the client retries with the `requestState` it was given.

What a client receives when a call needs the person's account depends on its revision and capabilities: `-32042` (older clients), an `input_required` result with a URL elicitation and a sealed `requestState` (2026-07-28 clients that declared URL elicitation), or a tool error with the link in its text (2026-07-28 clients that didn't). See [MCP protocol support](/docs/server-authors/mcp-protocol#connect-your-account-as-a-question). Errors from the MCP server pass through; a tool's own failure is a normal result with `isError: true`.

## Calls that need approval

When an [approval rule](/docs/teams/approval-rules) covers a `tools/call`, the portal records a pending request for that exact call and answers with a link to it instead of forwarding:

- a 2026-07-28 client that declared URL elicitation gets an `input_required` result with the link and a sealed `requestState`;
- another 2026-07-28 client gets a tool error (`isError: true`) with the link in its text;
- an older client gets `-32042` with the link.

The call record's outcome is `needs_approval`. Once a reviewer approves, the client retries the same call with the same arguments, within the approval's validity (15 minutes by default); the portal never replays it. A denied request answers with a tool error until it is explicitly renewed. A governed call can't continue a server's own elicitation, isn't retried, uses the server's primary endpoint only and is never run as a task. See [Approvals](/docs/use/approvals).

## Tasks

Since v0.9.0 the portal relays the [MCP Tasks extension](/docs/server-authors/tasks) for 2026-07-28 requests only. A `tools/call` becomes a task when the request declares `io.modelcontextprotocol/tasks` in its `_meta`, the server advertised the extension when the portal last read it, and the call is neither governed by an approval rule nor streamed. The answer is then a task with the portal's own opaque handle, never the server's task ID.

- `tasks/get`, `tasks/update` and `tasks/cancel` must declare the extension too (`-32021` otherwise) and carry `Mcp-Name` equal to `params.taskId` (`-32020` otherwise).
- Every lifecycle request is authorized again for the credential that started the task. An unknown, expired or foreign handle, or a task whose tool, definition or access changed, is `-32602` `Task not found`.
- Each lifecycle request is sent to the server once, never retried. A busy task is `-32010` `task_busy`; a task that wants input the client can't give is `task_input_unsupported`.
- A handle lives at most `TASKS_MAX_TTL` (24 hours by default), and one person or service account holds at most `TASKS_MAX_OPEN_PER_PRINCIPAL` unfinished tasks (100); at the cap a new task call is `-32010` `task_capacity` and nothing is sent ([Configuration](/docs/operate/configuration#mcp-tasks)).
- There is no `tasks/list`, `tasks/result` or task notification. Cancelling doesn't prove the server stopped.

## Retries and failover

The portal retries a failed read-class tool call, `prompts/get` or `resources/read` at most twice, and a server's team can add [failover endpoints](/docs/teams/protection-and-failover). The client sees neither, except in timing: one request is one logical call and one call record, within the server's original timeout. Writes are never resent when they may have reached the server. A server's circuit breaker, open after five consecutive failures on a replica, answers `-32010` `circuit_open` for 30 seconds without contacting the server.

## Results

Results are relayed with `_meta["io.modelcontextprotocol/serverInfo"]` removed and `structuredContent` dropped when it isn't an object. When a server in OAuth mode echoes the caller's token, it's replaced with `[REDACTED]` before the result reaches the client.
