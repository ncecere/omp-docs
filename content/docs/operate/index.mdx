---
title: Running Open MCP Portal
description: "For operators: what Open MCP Portal needs, how to install it with Docker Compose or Kubernetes, and how to run it."
---

Open MCP Portal is one stateless binary, `open-mcp-portal`, in one container image. It needs:

- **PostgreSQL 17**: the only state. Every replica shares it, including rate-limit counters.
- **An OpenID Connect identity provider** for sign-in.
- **TLS in front of it**: `APP_URL` must be https (an ingress or reverse proxy terminates TLS).
- **Two secrets** you generate: `ENCRYPTION_KEY` and `API_KEY_PEPPER`.

There is no worker, cache, queue or object storage. The binary serves the web app, the management API, the MCP endpoints, the OAuth endpoints and the background loops (health checks, signing-key rotation, retention, usage rollups).

<Callout type="warn" title="Pre-1.0">
These docs describe Open MCP Portal v0.2.0 (2026-10-18). Its image is published as `ghcr.io/ncecere/open-mcp-portal:v0.2.0` and signed with cosign: [check the signature](/docs/operate/compose#the-image) and deploy by digest. Coming from v0.1.0? Read [Upgrading from v0.1.0](/docs/operate/migrations-and-upgrades#upgrading-from-v010) first.
</Callout>

| Command | Does |
|---|---|
| `open-mcp-portal serve` | The web app, APIs, MCP endpoints and background loops (the default) |
| `open-mcp-portal migrate` | Applies database migrations and exits |
| `open-mcp-portal doctor` | Checks the configuration, PostgreSQL, migrations and keys ([Health and doctor](/docs/operate/health-and-doctor)) |
| `open-mcp-portal rotate-keys` | Re-encrypts stored secrets after an `ENCRYPTION_KEY` change ([Secrets and key rotation](/docs/operate/secrets-and-key-rotation)) |
| `open-mcp-portal version` | Prints the version |
