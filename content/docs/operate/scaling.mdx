---
title: Scaling
description: "Run several Open MCP Portal replicas: what's shared in PostgreSQL, which background loops run once, and how to size the database."
---

Open MCP Portal is stateless: scale it horizontally. Any replica can serve any request; there are no sticky sessions. Browser sessions, sign-in state, rate-limit counters and everything else live in PostgreSQL. `/mcp/{slug}` keeps no MCP session between requests.

## Background loops

| Loop | How often | Runs on |
|---|---|---|
| MCP server health checks | `HEALTH_CHECK_INTERVAL` (5 minutes) | One replica at a time (advisory lock); a server checked within the last 90% of the interval is skipped |
| Identity signing-key rotation | Checked hourly | One replica at a time |
| Notifications (fan-out, delivery of email and webhooks, the hourly scan for expiring keys) | `NOTIFICATION_INTERVAL` (15 seconds) | One replica at a time (advisory lock) |
| Retention (also deletes expired MCP task rows) | `RETENTION_INTERVAL` (15 minutes) | One replica at a time |
| Server governance (overdue reviews, sunsets, deprecation notices) | Every 5 minutes | One replica at a time (advisory lock `omp.governance`) |
| Background refresh of connected accounts' tokens (optional) | `PROVIDER_REFRESH_INTERVAL` (`0`: off) | One replica at a time (advisory lock) |
| Usage rollups | Every 5 minutes | One replica at a time |
| Old rate-limit windows; expired and idle sessions and consent links | Every minute; every 15 minutes | Every replica (idempotent deletes) |
| SCIM clean-up of people the directory deleted | In bounded passes, retried until nothing is left | Every replica |

`omp_loop_leader{loop="retention"}`, `{loop="usage_rollup"}`, `{loop="notifications"}` and `{loop="governance"}` say which replica led each loop's latest run. Runs are short, so the gauge can be 1 on several replicas at once.

Expired gateway grants stop working at their deadline on every replica; cleanup removes the rows later.

## Settings caches

Some settings are cached per replica for up to 30 seconds: internal networks, rate-limit settings, redaction patterns. The replica that saves a change applies it at once; the others within 30 seconds. Trusted clients, team overrides and gateway limits are read on each request.

## Rate limits

Limits on `/mcp/{slug}` (including each upstream server's quota), the OAuth endpoints, connection starts, sign-in and the management API are counted in one PostgreSQL table in fixed one-minute windows, shared by every replica. One `/mcp` request is one statement. A single gateway's counter row is fine up to a few thousand requests per second. The table is unlogged: counters may be lost on a crash or failover, which only resets the current minute. Client addresses are stored only as SHA-256 digests. Put the ingress's own limits in front of unauthenticated traffic, which isn't counted.

## State kept per replica

A few things are deliberately kept in each replica's memory, not shared:

- **A server's concurrency cap** (`maxConcurrent`) counts calls in flight on one replica. Across the fleet a server can receive about the cap times the number of replicas.
- **A server's circuit breaker** opens on one replica after five consecutive failures there, for 30 seconds. Replicas briefly disagree; `omp_server_circuit_state` is reported per replica.

Shared in PostgreSQL: server quotas, and the open-task count of `TASKS_MAX_OPEN_PER_PRINCIPAL`. See [Protection and failover](/docs/teams/protection-and-failover).

**Approval decisions** take a fail-closed table lock: when concurrent authority writes or database maintenance hold it, a call that needs approval is refused, not delayed. Keep autovacuum on.

## The database

Each replica holds a connection pool; size PostgreSQL's `max_connections` (or a pooler) for replicas × pool size. `omp_db_pool_*` metrics show how busy the pool is.

A call holds a request for up to its server's timeout (at most 120 seconds) and at most 1 MiB each way. Calls are buffered, except a `tools/call` that asks for progress, which is streamed (up to 64 progress events and 4 MiB) and needs an ingress that doesn't buffer: see [Ingress](/docs/operate/kubernetes#ingress).
