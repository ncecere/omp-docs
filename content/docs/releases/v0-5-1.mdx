**Released 2026-10-28.** [GitHub release](https://github.com/ncecere/open-mcp-portal/releases/tag/v0.5.1) · image `ghcr.io/ncecere/open-mcp-portal:v0.5.1` · no migrations (the schema stays at `00042`).

A reliability patch for [v0.5.0](/docs/releases/v0-5-0). **No feature, API operation, setting or schema change.** Upgrading from v0.5.0 is an image swap.

## What changed

- **Provider token refresh under a small connection pool.** Refreshing a person's or a shared connection's provider token used to need a second database connection while it held the first, so with a small runtime pool the refresh could wait on itself until its deadline and fail. The refresh now reads what it needs on the connection it already holds, with one deadline covering the lookups and the HTTP exchange.
- **The same checks, in the same places.** Address-policy checks still run before the request and when dialing, and a failed policy read refuses the exchange instead of using a cached answer. Linked-provider and endpoint checks still run before client credentials are attached. A narrowed personal token is cached only after its refresh commits.

## Upgrading

1. Pin the new image (verify its signature first, see [The image](#the-image)). No migration runs.
2. From v0.4.x or earlier, follow [Upgrading in v0.5.0](/docs/releases/v0-5-0#upgrading) first: an older image doesn't enforce approval rules even though it runs against the schema. Keep autovacuum on in production.

[Upgrading from v0.5.0](/docs/operate/migrations-and-upgrades#upgrading-from-v050) has the same points with the details.
